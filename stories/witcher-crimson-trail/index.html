The filename said EN. The game was Russian.

The Witcher file we were working with had EN in its name. Its actual resources were Russian. We followed what was inside the package.WT01

What was actually there.

Earlier MIDP compatibility work supplied the starting interfaces. The original joystick codes still needed their own meanings, and absent optional splash files could fall through to the game’s original PNG path rather than becoming a reason to invent replacement art.WT02WT03

Then we found a more consequential gap in the checkpoint. The RMS persistence code survived in the original APK DEX, but its Java source was missing. We kept that compiled implementation instead of guessing how to rebuild its storage behavior.WT04

Another session needs original defaults.

Original Quit and restart required fresh session values for static fields. Restoration used values from the original class initializers so a later launch began from the intended defaults, while record stores retained their separate job.WT05

The older notes keep the opening and first-level/RMS checks. Our later framework fixture checks the shell and Quit/static restoration without executing those preserved RMS save methods. There wasn’t a retained gameplay image in this checkpoint to add here.WT06WT07

About these records

This chapter describes the supplied Russian Nokia N73 Java ME edition. The preserved RMS DEX and later test boundaries are stated separately. Historical notes are not relabeled as a newly captured game run, and no missing gameplay image has been reconstructed. The source window is narrower than a complete recovery chronology.

WT03 / Absent optional splash files have an original PNG fallbackCheckpoint investigation notes

The original tries optional s.ani/s.bgs splash animation, catches their absence,

WT04 / The missing RMS source survives as original DEXCheckpoint investigation notes

Source: Witcher_Crimson_Trail_Bridge_v0.1.2_PRIVATE_CHECKPOINT.zip / Witcher_Crimson_Trail_Bridge_v0.1.2_PRIVATE/ORIGINAL_RMS_PROVENANCE.txt · selected lines 1–20

Original RecordStore binary provenance, private build

Source: Witcher_Crimson_Trail_Bridge_v0.1.0_PRIVATE.apk (original signed APK).
The original v0.1.0 checkpoint contained the adapted JavaME runtime but not
source for the following six javax.microedition.rms classes:
  RecordStore, RecordStoreException, RecordStoreNotFoundException,
  RecordStoreNotOpenException, RecordStoreFullException, InvalidRecordIDException.

The script tools/restore_original_rms_classes.py selects the six class_def
entries from the original APK classes.dex and retains their ORIGINAL DEX bytecode,
method code, strings and constant pools. It does not decompile/rewrite those
classes or implement substitute saves. The selected class definitions were then
passed to Android's D8 compiler to emit the minimum-api-26 prebuilt DEX at:
  runtime/prebuilt/witcher-original-rms.dex
SHA-256: 22d606e12fc4f7df87125c3b0f0cbe857d89e92accd2059c8eb757bc92f05d33

BUILD_LINUX.sh merges that DEX into the signed application alongside the
same original game JAR, engine and source compatibility code.
These classes were included in the rebuilt DEX and passed tooling validation,
but save behavior must still be verified on an actual Android device.
WT05 / Quit and static restoration use original initializer valuesCheckpoint investigation notes

Source: Witcher_Crimson_Trail_Bridge_v0.1.2_PRIVATE_CHECKPOINT.zip / Witcher_Crimson_Trail_Bridge_v0.1.2_PRIVATE/NORMALIZATION_NOTES.txt · selected lines 5–12

Changed MainActivity only for kit configuration, explicit inline original keypad,
hardware-source ownership, saved mode, startup fault capture and real Back cleanup.
Engine now fences actual teardown off the UI, uses native d.l() Quit, lets the
original worker run destroyApp (which saves via d.h and closes audio via d.i),
and restores the previous uncaught handler when it owns it. OriginalSession
captures original non-final static fields after their actual class initializers,
then restores fresh copies on re-entry after old teardown completes. It does not
invent game values, modify persisted data or alter original gameplay timing.
