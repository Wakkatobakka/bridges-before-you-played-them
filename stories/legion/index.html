A report writer escapes the game it diagnoses

RE4 Zeebo → Katamari

In Katamari, we explicitly followed RE4 Zeebo 0.1.9’s cached snapshots and independent writer. Its blocked-session test shows why that was useful: a report could finish while the game lock was held.KT13KT14

The stack inside one game.

By Biohazard: The Episodes, we had a clear cross-section of the pile. Its notes credit Monster Hunter for model/render/audio foundations, Snowboarding for the float adapter, DeadShot for per-contact input, Genesis for presentation and reporting, Wolfenstein/DOOM for bars and cutouts, and Contra for completed frames and quieter ordinary execution.BE02

We still had to fix Biohazard’s own problems. Its camera used the wrong canvas height, and a held action could change native identity after a context switch. The borrowed work got us far enough to expose those particular gaps.BE12BE15

What still belongs to the game.

We couldn’t treat every useful repair as universal. Katamari counted releases for its charge action. Duke’s simultaneous walk/turn behavior needed measuring in Duke. Mutant needed its actual input checked even where its printed help disagreed. Each game had the next say in whether a borrowed piece fit.KT04DU05MA08

That’s the part of the whole I can see when I look at the individual bridges. We start from something another game helped us understand, then find the next missing part. The failures belong in these stories because they explain where the useful pieces came from.L01WR10KT11

The earlier bridge returned the same bitmap object for QueryInterface(0x01001029), although that IID is ITransform. The later native transform call therefore reached an IBitmap vtable with the wrong method layout. v0.1.2 supplies a separately typed ITransform view retaining the original backing bitmap. The supplied v0.1.1 video starts after the combat freeze. It shows the stopped frame but does not capture the initial trigger. The short original first-guard host route reproduces the same fault with matching object/registers and LR00117BC0. The native matrix is [0,-256,256,0], a transparent 16x16 quarter rotation at destination (-1,17). The release runtime passes this route and further combat: original player HP100->97->94->91, pistol ammo10->6, guard HP40->24->9->0 and corpse flag, then movement Y1376->1312 with continuing timers. Evidence includes the pinned v0.1.1 comparison and current runtime hash. VERIFICATION.txt records the tested scope. No physical v0.1.2 run has been supplied.

R09 / Monster Hunter lessons enter Rockman’s mesh passCheckpoint investigation notes

Source: Rockman v0.3.3 preservation / PATCH_NOTES.md · selected lines 3–18

Preserved inside the original 0.3.3 archive retained by the later checkpoint.

## Why this build exists
v0.3.2 proved that Area 5's decoded D4D world mesh is live on-device: 3,241 vertices, 2,497 triangles, eight topology records, no GL errors, and full-frame GPU presentation. Visually, however, the entire stage used one flat color, so correct geometry and incorrect giant polygons were hard to distinguish.

Monster Hunter i v0.0.7 independently reinforced two lessons for the shared DoJa 3D work: surface orientation/backface behavior matters, and near-plane handling needs to be measured rather than guessed. This build borrows those lessons without transplanting Monster Hunter-specific game code.

## Changes
- Preserves the v0.3.2 D4D decode, world coordinates, camera path, Figure renderer, audio, controls, and GL-to-Android presentation bridge.
- Keeps all eight D4D topology streams separate through rendering instead of flattening them into one index buffer draw.
- Draws each topology/material stream with a stable neutral shade so stage segmentation can be seen before texture decoding is implemented.
- Builds a deduplicated depth-tested wireframe edge buffer from the decoded 2,497 triangles and overlays it on the filled stage.
- Adds D4D near-plane and winding telemetry: triangles wholly before the near plane, near crossings, far rejects, in-depth triangles, and CCW/CW/degenerate winding counts.
- Clips diagnostic screen-bound calculations to the active near/far range so near-zero perspective divisions no longer explode telemetry into meaningless million-pixel bounds.
- Does not enable backface culling yet. v0.3.3 gathers the winding evidence first so the next pass can choose the correct orientation rather than risking a blind scene disappearance.

## Expected visual result
The stage should no longer read as one featureless flat slab if the topology is coherent. Individual surface groups and triangle edges should become visible. This is still an untextured diagnostic render, but it is intended to distinguish real floor/wall structure from bad topology immediately.

## Models and animation

MbacMesh decodes original MB bone-local vertices, hierarchy, topology, per-corner UVs, material/texture slots, colors and appearance patterns. Texture decodes the original BMP resources used by Figure. Figure batches use original texture/material selection and upload to the preserved GLES1 backend; unavailable textures retain a defined geometry fallback.

ActionTable and MtraAnimation decode the original MT actions rather than supplying an empty duration. Action maxima and the guest's setTime remain Q16 frame values. Figure evaluates bone channels and composes them through the original hierarchy, applying the pose to the corresponding bone-local vertex ranges. Pose changes refresh the GLES vertex buffers; topology and source resources are retained. setAction starts the selected action at zero, and the guest then advances its own time. Animated appearance patterns follow the same action/time state. Monster Hunter supplied useful shared-format decoding knowledge; Rockman's presentation continues through ui.graphics3d/D4D/GLES rather than its incompatible opt.ui.j3d renderer.

CR02 / The timer was charged for work twiceCheckpoint investigation notes

Source: 11-Contra_4_Bridge_v0.1.1_PRIVATE_CHECKPOINT.zip / Contra_4_Bridge_v0.1.1_PRIVATE/TECHNICAL_HANDOFF.txt · selected lines 13–19

One HandlerThread owns native execution, timer pumping, saves, reports and all MediaPlayer callbacks. Android focus loss and lifecycle suspension stop scheduled gameplay and release input. Native background/resume events retain ordering even if the Activity changes quickly.

Timer pacing uses the deadline recorded at the actual native IShell.SetTimer call. The original Contra callback already requests max(20, 80 - native frame elapsed) milliseconds. v0.1.0 subtracted the whole Android tick time again; v0.1.1 waits only the time remaining after registration and checks that a timer is due before pumping it. Input and audio can update the queued deadline, but do not pump timers themselves. No queued tick remains when the guest has no timer.

Bitmap cache validity uses exact byte-range watches indexed by memory page, replacing whole-page versions. Writes outside a bitmap's header, backing memory and palette no longer invalidate its decoded pixels. Actual overlapping writes invalidate the cache; pointer or size changes rebind watches and released bitmaps remove them. RGB565 guest writeback remains immediate. The original executable, drawing order and guest memory format remain intact.

Production operations return independent pixel snapshots only when the framebuffer revision changes. Attach and explicit report capture retain full-frame reads. The controller retains a pending snapshot across same-revision audio results so a new image is not lost before Android receives it.
