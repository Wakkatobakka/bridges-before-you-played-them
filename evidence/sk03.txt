LOCAL KIT INTEGRATION FIX
The supplied v1.0.1 setKeypadVisible() correctly releases only touch inputs,
but its openMenu() still called releaseAll(), clearing held hardware before
its mode selector could run. The embedded app/src copy instead releases only
touch input on menu entry. Transient menu/help dialogs forward key-up events
for already-held hardware to BridgeInput.physicalUp(), preventing a release
from being lost while a dialog owns input focus. New menu-navigation key presses
are not injected into the running game by these listeners.
The exact integration diff is evidence/ui-kit-integration.patch.
app/ui-kit/ retains the unchanged supplied reference kit and compiled JAR;
app/src/com/wakka/bridgeui/ is the actual compiled source, including this fix.
