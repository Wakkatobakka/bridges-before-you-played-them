Outcome
Compiled native ARM batches consistently reduce calling-thread desktop CPU
by about40% for exactly the same original-game work. This is a substantial
execution-efficiency result, not a measured phone-cooling or FPS result.

Measured comparison
Exact delivered v0.1.6 Java interpreter versus v0.1.7 native-enabled candidate.
Four independent Linux x86_64/OpenJDK17 JVMs; two per workload, reversing the
first execution order. Each variant receives192warmup callbacks before timed
work. Each process records8alternating pairs of32callbacks. No profiler/JFR.
Current-thread CPU includes JNI/native instructions, but excludes background
JIT/GC and other app threads. Native loading is required and explicitly proven.

Implementation
C++ interprets the unchanged original ARM instruction stream in batches of at
most8192instructions. Java retains Thumb, unsupported ARM and original BREW
host services. The original renderer, clocks, native instructions, physics,
content, atomic saves, media and functional budgets remain. No FPS cap, PC
profiler, busy-loop bypass or guest state patch is added. The requested2ms
delay is not a rendered-frame rate. Faster callbacks can change real callback
throughput under the preserved scheduling, so40% less CPU per work does not
establish40% less whole-process phone CPU or heat.
