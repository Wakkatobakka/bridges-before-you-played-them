Native key lifecycle independently verified
- Keymanager vtable 0x102508: +4 query pressed 0x12C898; +0x14 press 0x147A04;
  +0x1C release 0x147A40; +0x20 last key 0x12C8BC; +0x24 cleanup 0x212E88.
- Press sets pressed[index]=1, released[index]=0 and last key = index.
- Release sets released[index]=1 and last key = 98 (sentinel); the pressed bit stays
  set until original cleanup clears pressed/released following native input.
- Independent fresh runtime probe read these exact fields before/after DOWN,
  release before callback and one callback. See native_key_fields.txt and source.
- Consequently press+release before a native callback can erase menu last key
  before a menu sees it. Serializing release after at least one naturally due
  native callback preserves an ordinary phone key press without host timer pumping.
- World pressed array queries can observe one post release sample, as native code
  explicitly defers cleanup. Do not override that lifecycle in guest memory.
