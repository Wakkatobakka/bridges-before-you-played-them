## Loading comparison

| Desktop JVM/Mesa | First-map loading |
| --- | ---: |
| v0.1.3 original ARM loader | 33.820 seconds |
| v0.1.4, new empty disk cache | 5.682 seconds |
| v0.1.4, warm disk cache | 4.851 seconds |

These are single controlled desktop runs, not phone performance measurements.
The same original new-game choice is driven through native input. Original
startup/intro timing changes the number of confirmation presses needed. Timing
starts at the confirmation that triggers the original loading-plaque flag,
then includes original progress frames, decompression, map setup, texture
uploads and three verification swaps after native gameplay becomes active.
Menu waiting before the map request is excluded. No background tests ran during
the final timings. The cold run uses a new unique empty cache directory and
asserts real host decodes; the warm run reuses it and asserts disk hits. Baseline
came from the preserved v0.1.3 source without profiling instrumentation.
The earlier fixed-frame navigation/connection-state timing attempts were not
used for these results. Baseline timing was retained while cold/warm were
repeated to verify cache conditions. Raw logs and summary accompany the build.

The new run avoided 28,688,578,258 bytes of repeated read-handle backing copies
across startup/menu/first-map opens. This is avoided allocation/copy volume,
not additional persistent memory or a measure of disk reads.
